# android/vpntun

TUN-интерфейс → userspace TCP/IP стек (gVisor netstack) → существующий
CONNECT-протокол. Делает из приложения полноценный VPN-клиент.

## Сборка у себя

Зависимость `gvisor.dev/gvisor` не удалось скачать в среде без сети —
добавьте и подтяните сами из корня репозитория (это уже основной
модуль `turboflare-transport`, не отдельный):

```bash
go get gvisor.dev/gvisor@latest
go mod tidy
go build ./...
```

**Важно**: после этого шага у основного модуля появляется внешняя
зависимость — `go build ./...`/`go test ./...` для ВСЕГО проекта
(включая `proto/`, `transport/` и т.д.) теперь тоже требуют сеть для
первой сборки (Go должен разрешить граф зависимостей целиком). Раньше
это было офлайн-собираемо — сознательный компромисс ради того, чтобы
VPN-функциональность собиралась в один `.aar` вместе с
`gomobilebridge`, без сложностей с разделением на несколько Go-модулей.

## Что нужно проверить после первой сборки

API gVisor `pkg/tcpip` менялся между версиями. Если `go build` в
`android/vpntun/tunnel.go` выдаст ошибки компиляции — сверьтесь с
реально установленной версией:

```bash
go doc gvisor.dev/gvisor/pkg/tcpip/link/fdbased
go doc gvisor.dev/gvisor/pkg/tcpip/stack
go doc gvisor.dev/gvisor/pkg/tcpip/transport/tcp
```

Конкретно проверить/поправить при необходимости:
- `fdbased.Options` — поля могли переименоваться
- `stack.New(stack.Options{...})` — набор полей
- `tcp.NewForwarder(...)` — сигнатура аргументов

## Известные ограничения текущей версии

1. **Один handshake на каждый TCP-flow.** Каждое перехваченное
   TCP-соединение (например, каждая вкладка браузера, каждый запрос
   приложения) открывает **свою** протокольную сессию — свой X25519
   handshake + CONNECT. Формат фрейма уже несёт поле `stream_id` именно
   для мультиплексирования многих потоков через одну сессию
   (`proto/frame.go`), но серверная часть (`server/server.go`) пока
   поддерживает только одно исходящее соединение на сессию. Полноценный
   мультиплексированный CONNECT — следующий логичный шаг, не реализован
   здесь.
2. **UDP обрабатывается только для DNS (порт 53).** DNS-запросы
   перехватываются и релеятся как DNS-over-TCP (RFC 1035 §4.2.2) через
   **одну** постоянную CONNECT-сессию на `1.1.1.1:53`, открытую один
   раз на весь срок жизни туннеля, с сериализацией запросов через
   mutex (одновременно обрабатывается один DNS-запрос — простое и
   корректное решение, но ограничивает пропускную способность при
   очень большом количестве параллельных DNS-запросов). **Весь
   остальной UDP-трафик** (QUIC/HTTP3, игры, WireGuard-внутри-VPN и
   т.д.) по-прежнему не обрабатывается вообще и отбрасывается.
3. Каждый flow держит отдельный `client.Client` с собственным
   congestion control/state — при большом числе одновременных
   соединений это может создать заметную нагрузку на сервер (много
   параллельных handshake). Для персонального использования (один
   пользователь, разумное число приложений в split tunnel) это
   приемлемо; для десятков одновременных пользователей — нет, но это
   не входит в объём личного research-прототипа.

## Что дополнительно проверить у себя (DNS-relay, gonet UDP API)

Сигнатура `gonet.NewUDPConn(stack, waiterQueue, endpoint)` в
`tunnel.go` написана по документации пакета, но, как и с TCP-веткой
раньше, могла разойтись с реально установленной версией — если
компилятор выдаст ошибку именно на этой строке, сверьтесь через
`go doc gvisor.dev/gvisor/pkg/tcpip/adapters/gonet` и поправьте
количество/порядок аргументов.

## Тестирование

Собрать и протестировать этот пакет можно только на реальном Android-
устройстве (TUN-интерфейс — привилегированная системная функция,
недоступна в обычных unit-тестах). Рекомендуемая последовательность:

1. Соберите `.aar` (см. `android/README.md`)
2. Установите APK, дайте разрешение VPN
3. Выберите 1-2 приложения в Select Apps (например, браузер)
4. Start VPN
5. Откройте выбранное приложение, проверьте, что интернет работает и
   реально идёт через тоннель — сверьте по логам сервера (`journalctl
   -u turboflare-server -f` на VPS должен показывать активность) и по
   IP, который видит сайт вроде `whatismyip.com` изнутри выбранного
   приложения (должен быть IP вашего VPS, не телефона)
